# Rung W2 scope — Findings: three stacked banners become one Review entry point

Prepared 2026-09-13 while W1 sits on its Human gate (needs a browser click-through) and Codex's T2 rung
is in progress. Investigation only — no code changed by this note. Read `ladder.md`'s own W2 entry
first; this is the concrete code map underneath it.

## The three banners, as they exist on `main` today

All three render into fixed `<div>` slots inside `#view-findings` (`neurosearch/web/index.html`
lines 185, 198-199), in this DOM order:

1. **`#staleFindings`** — `renderTriageCard('staleFindings')` in `neurosearch/web/js/research.js`
   (~line 653). Renders when any source is stale, legacy-unverified, or currently rebuilding. Up to
   four priced rows, each with its own button set:
   - `rebuild_matters` (stale AND carrying weight) → `rebuildBtns`: "Rebuild · $X" (primary when no
     faster option exists) + optional "📦 Rebuild in the background · $X" + optional "⏩ Rebuild now
     · $X" (primary when present).
   - `rebuild_transcript` (transcript changed) → same `rebuildBtns` shape.
   - `retry_failed` (last rebuild failed) → `retryBtns`: "Retry N · $X" + optional fast-path button.
   - `accept` (stale only because the brief changed, no weight) → `acceptBtns`: "Accept N as still
     usable" (free) + "Rebuild · $X anyway" (ghost) + optional fast-path.
   - Card-level dismiss: "Hide for now" (ghost, sets `STALE.left=1`, does not persist — reappears next
     session).

2. **`#fbSweep`** — rendered inline inside `loadWorkbench` (~line 848) from `r.low_value_sweep`, only
   when `st === 'approved'` (the current status filter is "approved"). One line: "N low-value findings
   nothing has used" style copy + "Review them" (small, sets three filters and reloads) + "Dismiss all
   N" (`small danger`, calls `sweepLow` which confirms via native `confirm()` then bulk-dismisses).

3. **`#fbQual`** — `loadQuality(st)` (~line 882), or `loadPromotable` when `st === 'reserve'`. Shows
   only for `st` in `{approved, suggested, reserve}`; empty for `dismissed`/`all`. Content depends on
   status:
   - `approved`/`suggested`: "🧽 Before you approve these: N the same source said twice · N that name
     nothing specific[, N protected][, N confirmed by more than one source]." + "Review" (small,
     opens a dialog via `openQuality`).
   - `reserve`: "📥 N of M withheld findings look worth keeping[, skipping ...]." + "Review" (small,
     opens `openPromotable`) + "Approve all N" (`small primary`, bulk-approves with no confirmation).

## A fourth (and sometimes fifth) banner the original audit pass didn't name

Between `#staleFindings` and the filter bar sits **`#suggestedWrap`** (`neurosearch/web/index.html`
line 186), rendered inline in `research.js` (~line 791). It can show up to two banners simultaneously,
independent of the three above:
- **Legacy suggestions**: "N suggestion(s) were generated by an older version and read as run-on
  sentences." + a bare text link "Re-analyse all" (not even a button — an `<a>` tag, its own small
  inconsistency) that calls `suggestNow(true)` directly with no cost disclosure or confirmation.
- **Analysing-in-progress**: a spinner + "Reading N sources for findings…" + an optional "⏫ Start N
  now" button (free — reorders the queue only) when a first-wave batch is queued.

So Findings can legitimately stack **up to five** banner-shaped things at once (triage card, legacy-
suggestions, analysing-progress, low-value sweep, quality/reserve) before the user reaches the actual
findings list — worse than `audit.md`'s H-3 evidence names by count, even if the visual severity is the
same root cause. This should fold into W2's scope, not be treated as a separate rung: it is the same
"why does this item need my attention" surface, just one more source feeding it.

## What's actually inconsistent (concrete, not impressionistic)

- Three different trigger conditions, three different data sources, three different fetches
  (`renderTriageCard` calls `/staleness/triage`; the sweep line rides along inside the main findings
  fetch; quality/promotable are their own endpoint calls) — so on load there are up to three
  sequential-ish banner-shaped things popping in at different times, not one coherent region.
  `loadQuality`'s own comment (0.61.2) already flags this cost concern for a 12,800-finding project.
  This is *also* an F2-adjacent concern (each banner has no shared loading state of its own — they
  simply appear or don't), but W2's job is consolidation, not the loading state itself.
- Three different bar-styling approaches: `renderTriageCard`'s card uses `border-color:var(--warn|line)`;
  the sweep and quality banners use plain `.banner`; none share a single "this needs your attention"
  visual treatment despite functionally being the same kind of thing (an item that wants a decision).
- Three different dismiss/defer models: the triage card's "Hide for now" is session-only (`STALE.left`,
  a JS variable, lost on reload); the sweep and quality banners have no dismiss at all — they simply
  stop appearing once their underlying condition clears.
- The audit's `H-3`/RC-A/RC-C framing (no attention model outside Research, and "stale" having five
  independent presentations) matches this exactly — Findings is one of the five.

## Every priced/actionable option that must stay reachable within ≤2 clicks (ladder's own behavioral gate)

Enumerated so implementation has a checklist rather than a vague "don't lose anything":

1. Rebuild (rebuild_matters) — primary/fast/background variants, ~4 buttons max in one row.
2. Rebuild (rebuild_transcript) — same shape.
3. Retry failed — 1-2 buttons.
4. Accept as still usable — free + optional rebuild-anyway.
5. Sweep: "Review them" (free, just re-filters) and "Dismiss all N" (destructive, currently gated by
   native `confirm()` — W2 doesn't have to keep `confirm()`, but must keep an equivalent count-visible
   gate per the ladder's explicit "a bulk-dismiss cannot be reached without the count of affected items
   on screen").
6. Quality: "Review" (opens dialog, free) for approved/suggested repeat-flagging.
7. Reserve: "Review" and "Approve all N" (free, bulk-approves with zero confirmation today — worth
   deciding whether that's intentional to keep or should gain the same visible-count treatment the
   ladder wants for the sweep's dismiss).
8. Legacy suggestions: "Re-analyse all" (paid — model cost — currently disclosed nowhere on this
   control; W1's own vocabulary/disclosure contract arguably already covers this one and it may be
   worth fixing as a W1 addendum rather than waiting for W2, since it's a disclosure gap, not a layout
   one).
9. First-wave: "⏫ Start N now" (free, reorders queue only — already discloses this via `title`).

## Why this is not being implemented blind right now

`ladder.md`'s own Behavioral gate for W2 requires checking "on the audit instance" that every one of
the above stays reachable with the same cost class and truthful estimate, and specifically flags this
as "the rung most likely to hide a priced action a user currently sees at once." That is a real-render
verification, not a code-reading one — implementing a banner consolidation this size without seeing the
result risks exactly the regression the ladder is warning about. W1's own Human gate is in the same
position for the same reason (needs a live/audit-instance click-through).

**Recommendation:** hold W2 implementation until an audit-instance (or live, read-only) check is
possible — for both F2's and W1's still-open behavioral gates, and to validate this scope note's banner
inventory is complete (e.g., whether `#suggestedWrap`, between `#staleFindings` and the filter bar, is
a fourth thing worth folding in — its own rendering wasn't traced here since it wasn't named in the
audit's H-3 evidence, but it sits in the same visual stack and is worth a look during the actual pass).
