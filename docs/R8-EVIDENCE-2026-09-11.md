# R8 storage evidence — 2026-09-11

This checkpoint records the repeatable storage measurements used for Foundation R8. Raw SQL was run against verified backup copies only; the live `data/neurosearch.db` was never opened.

## Backup integrity and shape

Backups `neurosearch-20260911-1628.db` and `neurosearch-20260911-1728.db` both returned `PRAGMA integrity_check = ok`, `page_count = 161831`, `page_size = 4096`, and contained `sqlite_stat1`. Both were 662,859,776 bytes with 105,048 `job_events` rows and 4,394 distinct jobs. The pair showed no file or event growth during the one-hour interval.

## Query-plan evidence

SQLite selected the intended indexes on both copies:

- `project_notes`: `ix_project_notes_project_status_source` for `(project_id, status, source_id)`.
- `messages`: `ix_messages_conversation` for `conversation_id`.
- `usage`: `ix_usage_kind_source` for `kind` and non-null `source_id` aggregation.
- `jobs`: `ix_jobs_kind_status` for `(kind, status)`.

The automated regression proof is `tests/test_s45_storage_hygiene.py` (**3 passed**). It also verifies the bounded connection cache, temporary storage mode, mmap enablement, durable `ANALYZE`, and seven-day rate limit.

## Gate status

The immediate R8 implementation/evidence portion is defensible. The 30-day job-event sample and a measured cold-versus-warm findings-quality scan remain open before choosing retention or changing the revision-scoped cache. No retention cutoff is authorized by this evidence.
