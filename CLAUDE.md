## Standing rules (never break these)

- **Never OPEN `data/neurosearch.db` from outside the running app — not to write, and not to read.** Opening it
  read-only crashed the live server on 2026-09-11 (0.63.32), twice. SQLite in WAL mode mmaps a shared-memory index
  (`-shm`) into every connection and decides "I am the only connection" from POSIX file locks. A session reaching
  the folder through a bridge mount from another OS/VM **does not see the server's locks**, so it believes it is
  alone and truncates `-shm` back to 32 KB on close — underneath a server that has those pages mapped. The next
  page the server touches is past EOF, and macOS kills it with SIGBUS (`Bus error, pagein past EOF`, inside a
  SQLite shm read). `mode=ro` + `PRAGMA query_only=1` **does not protect against this**: it forbids writes to the
  main database file and says nothing about wal/shm management, which a read-only WAL connection still performs.
  Only `immutable=1` leaves wal/shm alone, and the rule is simpler than remembering that.
  **How to measure instead, in order of preference:** the app's own API through Kyle's browser; `neurosearch`
  CLI on his Mac; or `cp` the newest file from `data/backups/` into the session's OWN workspace and open the copy
  there (never the copy in place). Hourly verified snapshots → `data/backups/`.
- Schema is additive (`CREATE … IF NOT EXISTS` + column adds in `db.py`); no migration tool. Migration fixtures in `tests/fixtures/db/`.
- **The model decision engine (0.54.0).** Every task runs the CHEAPEST tier (`contracts.TIERS`, ordered by `usage.PRICES` — note `claude-sonnet-4-6` $3/$15 ranks ABOVE `claude-sonnet-5` $2/$10) unless its contract names one of four reasons: `capability:<what>` (fact) · `evidence:<path>` (measured) · `irreversible` (debt) · `user:<who/why>` (opinion). Anything above the cheapest tier with no reason is a CONFIG ERROR refused by `release-check` — that refusal is the engine. `neurosearch models` prints the decision table. **`reversible` means the CONSEQUENCES are undoable, not that the call is cheap to repeat** (`rank.relevance` chooses which 20 of 400 videos enter the corpus, so it is irreversible however cheap re-ranking is). Everything at the cheapest tier must be reversible AND have a `gate`. Gate `tests/test_r6_model_policy.py`.
- **The local provider runs the CONTRACT's model (0.52.0).** `InferenceContract.local_model` (None = the contract's own model, the default for every task) is what Claude Code runs, via `contract.model_for(executed_by)`; `providers.routing_for` records `local_model`/`api_model` on the artifact whenever they differ. `NEUROSEARCH_CLAUDE_CODE_MODEL` is still honoured as a global override but `doctor` now names every task it overrides. Before this, one .env line silently replaced every per-task model — `findings.extract` and `rank.relevance`, both pinned to Sonnet 5 in `contracts.py` by measured comparisons (E2.1/E2.2; `findings.extract` has since moved to Haiku via `.env` — see the top of this file), ran on Haiku 4.5 on every local call with nothing recording it. A cheaper model is often right; it has to be a declared decision, never a side effect. Gate `tests/test_r4_local_model.py`.
- `providers.invoke(task, …)` / `invoke_structured` are the ONLY entry points for model calls; never pass model/max_tokens/headers at call sites. Every task has an `InferenceContract` in `contracts.py` with `fallback="NO_FALLBACK"` — no model substitution. This is distinct from transport fallback: local-to-paid execution now defaults OFF; `NEUROSEARCH_LOCAL_API_FALLBACK=true` explicitly permits it. `api_requested`/`api_only` remain explicit paid choices.
- **Every model comparison pins its transport (0.56.3, extended 0.56.5).** `migration.run_migration_compare`, `evals.run_findings_compare` and `evals.run_ranking_compare` all force `settings.ai_profile="cloud"` + policy `api_only` for their run (`evals.pin_api_transport` / `migration._force_api_transport`, restored on every exit path) and verify each arm's returned model (`arm_model_ok` / `_assert_arm_model`), failing on the FIRST offender. `findings.extract` and `rank.relevance` are `local_capable`, so the two commands that would decide Haiku for findings were the worst affected: both arms routed to the local CLI and neither ran the model it was handed.
 `migration.run_migration_compare` forces `settings.ai_profile="cloud"` + policy `api_only` for its whole run (`_force_api_transport`, restored on every exit path) and verifies each arm with `_assert_arm_model`, failing on the FIRST arm whose returned model is not the one it asked for. With `NEUROSEARCH_AI_PROFILE=local` in `.env`, every `local_capable` task (`planner.update`, `claims.extract`, `findings.extract`, `rank.relevance`) routed to Claude Code instead: both arms of `planner.update` printed `$0.0000 · returned claude-haiku-4-5` regardless of the model set, and the *shared inputs* every other arm is judged against were written by the local model rather than the production findings contract. `local` vs `api` is a transport, never a model.
- **A provider that returns a model nobody asked for is a silent substitution (0.56.3).** The app has no model-substitution code path, so a mismatch always arrives from OUTSIDE it — the local Claude Code CLI served `claude-haiku-4-5` for a call pinned to `claude-sonnet-4-6`. `providers.routing_for` compares the returned id against the requested one (`contracts.same_model`: a dated snapshot of the alias is not a substitution), stamps `model_mismatch` on the artifact, and counts it via `db.bump_model_mismatch` → `db.model_mismatches()`, surfaced in `db.health()["model_routing"]` and warned by `release-check`/`doctor`. Recording `actual_model` was never enough: nothing read it. Gate `tests/test_s1_arm_preflight.py`.
- **An arm that cannot run must fail before anything is paid for (0.56.2).** `migration.task_arms` builds no `candidate-adaptive` arm for a candidate that cannot do adaptive thinking (`supports_adaptive` = Claude 5 only, mirroring `contracts.validate`), and `migration.validate_arms` constructs EVERY arm's contracts before the first paid call — the arm-level twin of `preflight`, and it fails free the same way. 0.56.1's `--candidate-model claude-haiku-4-5` built an adaptive Haiku arm; the ContractError landed after two planner arms had been billed, so $0.39 of finished measurement died with the run. `run_migration_compare` now also writes its report from a `stage_error` path, so a stage that dies anyway leaves the completed stages measured and reported instead of discarded. Gate `tests/test_s1_arm_preflight.py`.
- **Background throughput may consume spare capacity. It may never consume foreground capacity (0.63.92, P0).**
  Measured 2026-09-17 (docs/SPEED-AUDIT-2026-09-17.md): a $0 Claims harvest holding SQLite's single writer for
  minutes, a 186 s transcript walk on the Sources poll, and a 12 s `dedupe_targets` transaction each turned "New
  chat" (one INSERT) into a minute-long wait. The rules that follow from it, each with a gate: no CPU loop or
  network call inside a write transaction — decide first, then write in a short `tx()`/`batch()` (chunks of
  `claims.HARVEST_TX_NOTES`); `db:write_hold` on `/api/perf` records every hold and logs any past
  `db.WRITE_HOLD_WARN_S` with its caller — a warning there is a P0 defect, not noise; a job's post-completion hook
  runs only after the job has left `_running` (`jobs.execute`) and queues work rather than doing it; nothing on a
  poll path walks a corpus (derive it — `sources.spoken_chars` — and index it); the browser bounds itself
  (`POLL`: one refresh of a kind in flight, 20 s abort on quiet requests, at most 2 quiet requests on the wire,
  no polling while hidden) — those four numbers are measured safety boundaries, changed only against a new
  measurement; and a UI edit never restarts the process (`reload_includes=["*.py"]`). Gates S65–S70, K9.
  A derived cache's revision moves only when its answer changes — never because a pass re-derived it (S72). The
  remaining floor is GIL sharing with CPU-bound background passes; a second process reopens ONLY on Kyle's trigger
  (docs/SPEED-AUDIT-2026-09-17.md §11): real use, foreground p90 > 1 s repeatedly, write holds < 250 ms, caches
  > 95 % hit, traces attributing the delay to background CPU. Durable work units are content-addressed by the
  full request (project framing, window, contract, execution, revisions, depth) — compute reuse, never
  project-state reuse: a shared unit materializes into each project's own rows and lifecycle (test_s46).
- **A per-pass cap is not a budget (0.51.0).** `claims.FAST_GROUPS` bounded one paid fast pass to 16 claims and nothing bounded passes per hour, so a paid pass was queued every ~5 min all day (32% of a month's spend). Any lane that can re-queue itself needs a RATE limit that the "enough work accumulated" test cannot bypass (`claims.FAST_MIN_INTERVAL_S`). `db.BACKGROUND_KINDS` (`extract_claims`) is paused by `background_paused` **whatever lane it runs on** — a control that exempts the thing it exists to stop is worse than no control. `usage.SPEND_RATE_CEILING` ($/rolling hour, maintained by `usage.record`) holds ONLY paid background (`db.RATE_HELD_POLICIES` + `BACKGROUND_KINDS`) — never chat, ingestion, transcription or local work — expires on its own, and is released by the user via `POST /api/usage/rate-resume`. Gate `tests/test_r3_spend_rate.py`.
- **Account gates are cached beliefs, not facts:** `providers:billing_until` and `providers:spend_cap_until` block the queue, and only a SUCCESSFUL call (`db.clear_account_gates()`, called by `providers`) or the user's explicit Re-check (`POST /api/usage/recheck`) may retire one. Never set a gate without a path back — `spend_cap_until` had none until 0.46.4 and a Console limit raise could not unblock the app. The same rule covers `claude_code.health`'s 10-minute cache (Re-check forces a fresh probe, 0.46.5) and a job's `message` (claiming clears a stale `paused:%` one, 0.46.5). **`extract_claims` runs on the `slow` lane** (p90 ~2 h against only 3 AI worker slots).
- `safe_fetch.safe_fetch()` is the ONLY way to fetch a user-supplied URL (yt-dlp is the documented exception). No second fetch path, no caller-side limits.
- Batch results enter the DB only through `batches.materialize_ready`; never claim a provider batch by count alone.
- Frozen numbers (Tier 1 totals, retrieval baseline, prefilter/rerank gates) are decisions: never re-tune an experiment to a fixture; changing a frozen value is recorded in HARDENING.md.
- API keys only in `.env`; cookies server-side (`data/cookies/`); Instagram only via the extension session, cap 40; no account cookies for bulk YouTube downloads by default.
- Eval policy: Tier 1 (`NEUROSEARCH_FAKE_AI=1 neurosearch eval`) + pytest always; live paid evals only for a major model replacement, a major AI-affecting architecture change, or a regression investigation.
- `project_sources.excluded=1` is a durable "removed from this project" marker: every membership query (direct, collection, tag) subtracts it; an explicit add lifts it. Never derive membership without it.
- New test modules must sort AFTER `tests/test_core.py` (it builds the shared settings/DB at import).
- **A milestone is not delivered until GitHub has it, verified against the actual remote (2026-09-22).** "Committed and tagged locally" is not delivery. After every `main` delivery: push `main`, push the intended tag if there is one, fetch again, and compare SHAs — then run `tools/git_sync_check.py --delivery`, which must exit 0. If a push fails the work may be locally complete, but it is reported as **NOT DELIVERED TO GITHUB**, never as done. `git ls-remote` is remote truth; a `refs/remotes/origin/*` ref is only a cache and is not proof a branch is absent. This rule exists because a 2026-09-22 audit used `git rev-parse --abbrev-ref <branch>@{u}` — which reports a branch's CONFIGURED UPSTREAM, not remote truth — and wrongly reported five branches as local-only when GitHub already had them. Never `git push --all` as cleanup; never force-push `main`; never force-update a published tag (`git tag -f` on a milestone is gone — create the tag only after the final commit exists, push it, then treat it as immutable). Do not auto-push scratch branches, but any branch holding unique durable work must either be pushed or have its commits reachable through another GitHub ref. `tools/git_sync_baseline.txt` records the refs that physically cannot be published (pre-purge history carrying >100 MB `VIDEOS/` blobs) and why; adding a line there is a reviewable act, not a way to silence drift.
- **A session does not need GitHub credentials to do engineering work, and must never ask Kyle to push for it (2026-09-22).** Publishing is HTTPS + the macOS `osxkeychain` helper, so a Cowork/Linux/VM session cannot push — but it can *request* publication. Every durable commit ends in exactly one of three states: **`PUBLISHED`** (exact SHA verified on GitHub by `git ls-remote`), **`PUBLISH_REQUESTED`** (exact SHA submitted, receipt pending), **`BLOCKED`** (the publisher refused or failed, with its reason). *"Committed on the Mac"* is no longer a terminal state, and *"Claude Code needs to push this"* is not an acceptable handoff line — request it instead: `.venv/bin/python tools/publish_request.py <sha>`. That writes a SHA-only request (never a secret) to a queue the Mac-native LaunchAgent `com.neurosearch.git-publisher` drains as Kyle's user; `tools/github_publish.py` then publishes **one exact SHA**, fast-forward only, refusing divergence, forbidden paths (`.env`, `data/`, `VIDEOS/`), credential-shaped strings and oversized blobs, never forcing, never merging, never touching the working tree or index — then proves the result with `git ls-remote`. Only a broken publisher is a GitHub-delivery blocker Kyle should ever see. **Never copy a GitHub credential into a VM, sandbox, repo file, `.env`, script or handoff document; never create a PAT in the repository.** The publisher and the sync gate stay separate: the publisher delivers one commit, `git_sync_check.py` audits the whole repo. Gate `tests/test_s81_git_publisher.py`.

## Foundation ownership boundaries

- `semantics.py` was removed in 0.63.36. It was a dormant all-row embedding/fixed-quantile experiment with no
  API, CLI, tests or callers and conflicted with the current active-only, multi-signal research policy. Do not
  restore it as an implied roadmap item. The unused additive embedding columns remain for schema compatibility.

- `jobs.start_workers` permits one live worker generation. `stop_workers` stops admission, drains workers, and only then stops heartbeats. A bounded shutdown that cannot finish raises and retains its thread registry; never clear it to make a test pass or start another generation over it.
- Each worker/maintenance thread binds its database path at startup and closes its own connection in a finally block. `db.close_thread_connection` never opens a database during cleanup.
- API tests use a lifespan without queue workers. They explicitly drive jobs. Tests needing worker behavior start and stop real workers on temporary databases; a shared API client must not silently process another test's queue.
- Tests establish production-safe defaults for every experimental/rollback flag before application imports. A local
  `.env` may not activate Planner V3, the prefilter, reranker, chat-tail breakpoint, schema fallback or fake AI in an
  unrelated test. A test that needs one opts in explicitly.
- `jobs.execute` establishes job/run identity before calling the task adapter. Logs retain the full run id; formatting alone may shorten it. This prevents adapters from omitting context, but does not prove the historical NULL-run-id cause is solved.
- Local provider failure with paid fallback disabled parks the same job for a local retry without consuming a job attempt. It is visible in the job message and provider status. Existing explicit paid choices still apply. Do not rewrite existing job policies or historical usage to implement this rule.
- All first-party UI requests use `uiFetch`, including uploads and chat streams. Versioned stale clients receive HTTP 409 before endpoint execution. The UI checks while visible every 30 seconds and when refocused, and offers Reload page without discarding drafts automatically. Unversioned API/extension clients remain supported; pre-0.63.36 tabs need one initial reload to acquire this guard.
- Findings-quality and usage caches are scoped to their actual inputs rather than global job heartbeats; list-style job polling omits captured page bodies while detail retains them. Claims cancellation is checked after model responses and during backlog assessment, and queued cancellations are finalized even while background lanes are paused.
- Read-only Health, Usage, backlog and staleness surfaces use `claude_code.health_snapshot()`. They report an
  unchecked or stale cached verdict without starting a CLI process. Explicit Re-check and actual local-provider
  routing are the probe initiators.
- `tests/test_s43_foundation.py` and `test_s44_frontend_integrity.py` are registered release gates. Static frontend gates cover column-zero global declarations, literal DOM IDs and static inline handlers; they are not a full JavaScript/DOM analyzer.

- "Scan this course" (introduced in extension 1.7.0; lesson cards + course documents landed in 1.9.4–1.9.6; mission CS, docs/COURSE-SCANNER-2026-09-15.md) is `extension/scan-lib.js` — one strategy-pipeline library loaded unmodified by `scanner.js`, `background.js` and `tests/js/run.mjs` (jsdom). Strategy A = linked lesson pages (`fetch()`); Strategy B = interactive SPA traversal (sequential `.click()`, `settle()` quiet-window/hard-cap, never a fixed sleep); Strategy C is folded into `findPlayers(..., {rendered:true})`, scoped to the active lesson so an SPA's serialized state blob is never credited to every lesson. `adapters = []` stays empty until a platform earns one; no platform-specific selector exists in the generic path (`test_no_platform_selectors_in_the_generic_scanner`). Durable scan state is per-tab (`scan:<tabId>` in `chrome.storage.local`, never a singleton), every message carries its `scan_id`, and an interruption is only tab close / origin change / an unanswered liveness ping — never a bare SPA URL change. `import_course` (`courses.py`) groups lessons by normalised video url before enqueueing: a video shared by lessons acquires once (`db.sources_for_urls` — the same derived-truth check as `add_page_videos`, no second "added" flag) but every lesson using it is still named in the response's `shared` list.
